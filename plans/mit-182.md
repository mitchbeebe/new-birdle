# MIT-182 — Custom region game from nearby eBird observations

Branch: `mit-182-custom-region`, based on `premium`. PR targets `premium`. Same plan is committed at `plans/mit-182.md` on the branch.

## Summary

Premium users configure one custom region (lat/lng/dist/back/includeProvisional) on their profile. Birdle fetches recent nearby observations from eBird once, builds a **frozen** species pool from the species codes that exist in our `Bird` table, and then the custom region behaves like any other region: a daily `Game` row, autocomplete limited to the pool, stats, share text. Decisions from the issue: one region per user, pool frozen at creation (a "Rebuild" button re-fetches), daily bird is a normal per-day `Game` for that region (fresh pick per region, no cross-user determinism), games count toward global stats.

## Reuse the Region machinery (key design choice)

Create a real `Region` row per custom region, `code = f"custom-{user.pk}"`, `name = "Near <lat>, <lng>"`, and `BirdRegion` rows for the pool. Then `random_bird`, `todays_game`, `Game`, `UserGame`, `bird_autocomplete`, and `stats` work with no changes to their queries. Only region *resolution/validation* changes.

## Data model

`CustomRegion` (OneToOne user): `region` (OneToOne `Region`, CASCADE), `lat`, `lng` (Decimal 2dp), `dist` (int, default 25, 1–50), `back` (int, default 14, 1–30), `include_provisional` (bool), `species_count` (int), `built_at`. Migration `0015_customregion`. Deleting a `CustomRegion` deletes its `Region` (cascade both ways or delete explicitly in the view). Register in admin.

## eBird client — `birdle/ebird.py`

`fetch_nearby_species_codes(lat, lng, dist, back, include_provisional) -> list[str]`: GET `https://api.ebird.org/v2/data/obs/geo/recent` with header `X-eBirdApiToken` = `settings.EBIRD_API_KEY`, `maxResults` omitted. Use `requests` if already a dependency, else `urllib`. Raise `EbirdError` on non-200 / network failure. Cache the code list in Django cache for 24h keyed on the rounded params (so rebuilding twice in a day doesn't refetch). `build_pool(custom_region)`: fetch, `Bird.objects.filter(species_code__in=codes)`, replace `BirdRegion` rows for that region atomically, set `species_count`/`built_at`. Settings: `EBIRD_API_KEY = os.getenv("EBIRD_API_KEY", "")`, derived `EBIRD_ENABLED`.

## Region resolution

Region validation in `daily_bird`, `stats`, `bird_autocomplete` currently uses the hardcoded `get_regions()` dict. Add a helper `resolve_region_code(request, region_code)` that returns the region code as-is for fixed regions and, for the public code `custom`, returns the logged-in premium user's `custom-<pk>` code (404 if they have no custom region, redirect to `premium` if not premium, login redirect if anonymous). URLs stay `/custom/` and `/custom/stats/`; the session `region_code` stores `custom`. Region dropdown (`get_regions` tag / `region` view) shows "Custom (near me)" only when the user is premium. Share text uses the custom region's name. Keep this surgical: one helper, called from the three places that validate region codes.

## Profile UI

Section on `profile.html` (premium only): form with lat, lng, dist, back, include provisional; a "Use my location" button that fills lat/lng via `navigator.geolocation` (no server change). Submit → create/update `CustomRegion`, create the `Region` row if needed, `build_pool`. Show species count, built time, "Rebuild pool" and "Delete" buttons, and a link to play `/custom/`. Errors from eBird render as a form error; a pool under 10 species is saved but shown with a warning. Views: `custom_region` (POST create/update/rebuild) and `custom_region_delete` (POST), both `premium_required`. New form `CustomRegionForm` in `forms.py`.

## Tests

`CustomRegionTests` with `ebird.fetch_nearby_species_codes` patched: pool built from a mocked response ignores unknown codes; empty response yields empty pool + warning; rebuild replaces rows; anonymous → login redirect, non-premium → `premium` redirect on `/custom/` and on the profile form; premium user with a pool can load `/custom/`, guess, and see stats; fixed region codes are unaffected; eBird error surfaces as a form error, not a 500.
